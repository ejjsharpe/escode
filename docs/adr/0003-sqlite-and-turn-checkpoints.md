# SQLite current state with explicit turn checkpoints

Subsequent amendment, 2026-10-31: [ADR 0004](0004-execution-events-and-t3-recovery.md) and the [execution specification](../specifications/execution-architecture.md) supersede current-state-only execution authority and blanket no automatic continuation. SQLite WAL `NORMAL`, provider-native context and explicit file checkpoints remain; the original decision below records the earlier scope.

Accepted by the user on 2026-10-31 after the durable-state grilling synthesis: adopt host-owned SQLite for authoritative metadata, conventional current-state tables with receipts/operation evidence and explicit turn checkpoints, while keeping complete transcripts provider-owned. These independent choices support inspect, rewind and isolated historical branching without application-wide event sourcing; the cost is explicit checkpoint retention, provider capability limits and non-atomic recovery across database, files and provider effects. Choose WAL with `NORMAL` for the flushing/latency trade-off, accepting possible loss of recent acknowledged metadata after an OS crash or power loss; preserve no automatic replay/continuation, add explicit emergency Stop during persistence failure and require a minimal consistent recovery-copy/restore mechanism.

The [accepted specification](../specifications/durable-state-and-time-travel.md) owns behavior, cleanup defaults, boundaries and qualification. This amends [ADR 0002](0002-versioned-recovery-and-history.md)'s storage mechanism and adds turn history; host authority, client-owned recovery, bounded provider delivery, fresh-store/no-import policy and uncertain-effect protection remain. No application implementation or runtime acceptance is claimed.
