## Subsequent durable-state and time-travel amendment

## Prerelease delivery amendment

It does not claim those checks passed.

- Start with fresh escode state. Do not import old chats, composers, recovery drafts, context associations or reservations. Do not build upgrade/downgrade support, legacy-writer coordination, old/new storage conversion or a backward-compatible transport. Initializing the new store must not delete old escode state, project files, provider history or existing worktrees.
- Replace internal feature paths directly and delete their superseded domain routes as each slice lands. Do not add compatibility adapters, dual dispatch or automatic fallback. Features not yet replaced may continue working through their current paths during development, under the same authority; this is not a supported transition release.
- Qualify the actual local installation, recording macOS, Electron, Node, Git and Codex versions and checking development and packaged execution. Broader installation/provider-version matrices are deferred; the older application's support claims do not establish compatibility for the new foundation.
- Defer exhaustive multi-client arbitration/recovery and device-revocation qualification until a second client is approaching. Retain stable client ownership, host-bound identities, command serialization and authority boundaries. No multi-client or revocation acceptance is claimed.
- Defer the full capacity benchmark matrix, five-run cold/warm sampling, prolonged steady-load and specified overload qualification. Retain a practical local baseline, explicit bounded queues/history/storage, cleanup checks and basic exhaustion tests, including stalled delivery and disk failure. Document initial limits and observed behavior without claiming measured production capacity or improvement percentages.
- Retain exact execution-context identities, uncertain-command protection, scoped replies/Stop, explicit-save conflicts and file-operation preservation. Restart/crash recovery within the new format remains required; it is distinct from importing legacy state. Keep new-format storage version checks and safe rejection of unsupported stores.
- Fold first-milestone, chat and Files acceptance into the feature delivery tickets, retaining one final integrated acceptance ticket. Each slice owns its relevant tests, packaged evidence, replaced-route removal and changed accessibility evidence. Phase outcomes remain prerequisites, confirmed from delivery evidence before the next phase starts; they do not require separate acceptance tickets or repeated full-suite runs at every boundary.

Implement small complete slices with focused packaged checks. One primary agent owns shared composition and integration; independent tickets can proceed in parallel once their prerequisite contracts and ownership are stable. Application implementation remains a subsequent effort.

## Selected architecture

One execution-host authority owns provider processes/credentials, approved contexts, filesystem/Git operations, watchers, durable metadata and reconciliation. Initially compose it inside Electron main. Renderer loss releases connections and views, never host-owned execution. A separately installed service is later work.

Introduce `packages/contracts`, `packages/host`, `packages/client-runtime` and the tracked `packages/effect-codex-app-server` source unit. Keep portable reconciliation in existing pure modules until extraction requires a shared package; do not create a general utility layer. Contracts depend on portable Schema/RPC declarations; host and client-runtime depend on contracts, never each other’s implementation. Neither imports Electron/React. Desktop supplies native/bootstrap/storage adapters and presentation. Existing pure `affected`, `moved`, `reconcileSave`, ordering and reducers stay ordinary TypeScript; React/Monaco own models, undo, focus and accessible presentation.

Effect owns I/O orchestration and scoped resources. Construct host Layers once per host, client supervisors once per desired host, sessions per connection attempt and subscriptions per view. Provider sessions are host-owned. Disconnect/cancellation cannot interrupt admitted provider work. Moving synchronous native work into `Effect.sync` is insufficient: measure host event-loop delay and move blocking execution behind asynchronous adapters while retaining descriptor checks.

Target exact Effect 4.1.0 core/platform-node/node-shared versions and the runtime report’s verified dependency closure. This is conditional on phase 0 runtime checks; no silent downgrade to v3 or mixed package families. The required Redis peer closure is an installation cost, not a running service. Retain Bun/Nx/Monaco and the existing test runner; adapt upstream tests rather than adding a parallel framework. Review unstable RPC/socket/platform APIs and T3’s 4.0.5 patches explicitly.

Adopt the tracked Codex transport as a coherent source unit, retaining generator metadata, schema source and compatibility widenings. Adapt T3 session/driver/supervisor, snapshot/replay/live, coalescer and LiveStreamBudget together. Preserve escode persistence, authorization and command uncertainty rather than importing T3’s application event store or restart continuation. Track upstream pin `305a90dce44b8b7813d951662f13ce8510a3c669`, copied files and local patches in an extraction manifest. Preserve T3 MIT and applicable generated Codex Apache-2.0/NOTICE attribution; produce distribution notices from the actual lockfile/artifacts. Whole-product adoption carries unnecessary provider/native/UI/database closure; isolated throttle copying omits correctness machinery. Both are rejected for this handoff.

## Wire, authority and durable state

Authenticated loopback WebSocket is the domain path. IPC retains narrow, sender/frame-validated local bootstrap and native picker/import/clipboard/Finder capabilities. Bind literal loopback only; use short-lived bootstrap/session tickets, validate packaged Origin/Host and endpoint path, verify persistent host identity and exact initial wire revision before data/commands. Remote routes stay disabled. Capabilities describe support, not authority. Every command revalidates approved root/object identity and resource/session revision at its mutation handoff. A path or native client selection alone grants no remote authority.

Use feature schemas for Chats, Files and Source Control, including typed unavailable/conflict/stale/denied/incompatible/overflow/uncertain results and safe unknown-provider payload presentation. Separate wire revision, storage version, entity revision and provider compatibility. Reject incompatible clients/newer stores without writing. Test the installed Codex version against adopted schema provenance and record the version; retain process-group cleanup. Broader provider-version qualification is deferred.

Snapshots capture projection and live tail atomically under a host-start epoch. Applied coverage cursors advance only after complete validated application. Duplicates/overlap are idempotent; gaps, expired replay and epoch changes require bounded resnapshot. Background summaries exclude transcript bodies; only observed details subscribe. Watch/Git events are invalidation hints with explicit rescan, not mutation facts. One Git refresh per checkout plus one dirty bit; retain two-second fallback while visible and reject stale selection results.

Durable command keys bind host, authenticated principal, ID, target and canonical payload digest. Serialize admission against expected state; record admission and dispatch intent before effects. Repeated IDs return status; changed payload/target conflicts. A lost result becomes uncertain and is reconciled through status/history, never automatic resend or a new ID. Restart never dispatches recovered Send/reply/continuation. Receipts cannot make external effects atomic. Replies consume an exact live request once; Stop targets the captured provider/turn or preparation token and remains available without its directory. Stop during preparation cancels that operation, preserving reservations and reporting partial effects.

Adopt the synchronization report’s bounded transient replay and receipt/admission-epoch design. Rotate admission epochs after restart/restore and before pruning permits old submissions to become executable. Never prune nonterminal uncertainty or operation evidence to admit work. Recheck authority on receipt lookup. Preserve originating-device attribution and authority interfaces for future revocation; its implementation and exhaustive race qualification are deferred. Completed external effects cannot be undone.

Initialize a fresh versioned store separately from legacy state. Persist stable host and client identities before publishing endpoints. Records created by the new implementation retain their UUIDs, paths, filesystem identities, reservations, provider identities and timestamps across restart. Preserve filesystem identities losslessly. Use durable writes and recovery records appropriate to the current format; interrupted writes must not silently replace identities or admit ambiguous effects. No legacy import or version-conversion framework is required.

Do not modify old escode stores or allocate new associations from their contents. Project files, existing worktrees and provider-owned history are not disposable application state. New-format recovery reconciles real outcomes; restoring stale application metadata cannot undo filesystem/provider effects or justify replaying a command.

Client-owned composer/recovery records use stable client identity, independent of connection attempts. Host records dirty-state obligations and per-client operation acknowledgements; one client cannot clear another’s protection. Disconnected known-dirty clients block destructive mutations until explicit safe resolution. Unknown unpersisted keystrokes retain the accepted best-effort limitation. New records belong to their creating client; there is no legacy composer/recovery import. Exhaustive second-client qualification is deferred.

## Bounded bodies and measured capacity

Store transcript text as immutable chunks referenced by message/body revision and byte range. Stream bounded append chunks; page older immutable chunks rather than retransmitting full growing bodies. A host-owned disk spool holds live chunks not yet recoverable from provider history; durable chat/provider identity remains separate. Persist a chunk/index before publishing a recoverable reference. Reconcile orphaned/partial chunks on restart; never attach them to a new host/chat. Client detail cache uses a bounded window and explicit page eviction; summaries contain no bodies. Provider history must be read incrementally or rejected at a bounded decode boundary: truncating after an unbounded JSON allocation does not pass.

Maintain independent limits for decoded frames, in-flight ACK batches, replay, client/host delivery, provider ingress, body cache, socket buffers, subscriptions, watchers, receipt storage and spool disk. Charge encoded bytes before enqueue, including in-flight data until ACK; also measure heap/RSS. Retain control/Stop capacity separately. On spool quota/disk failure, stop accumulating text, mark the affected body partial/unavailable and retain control/status plus provider identity. Stop remains usable; no silent turn cancellation. Continue draining bounded provider frames or fail the provider session explicitly if safe bounded decoding is impossible. Do not claim complete history or bounded memory otherwise. Evict only reconstructible chunks; never uncertainty, drafts or operation facts.

The synchronization report’s numeric values are experiment seeds only. Record explicit initial limits and verify their exhaustion behavior with focused tests; they are defensive settings, not measured production capacity. Observe actual queue/heap and event-loop behavior in practical packaged checks. Keep Stop/control capacity available when transcript delivery stalls.

Capture a reproducible local baseline before replacement: startup, chat opening/streaming/reconnect, directory updates and Git status/diffs, with timing and memory observations on recorded hardware/build/data. Compare the new packaged app against it for obvious regressions. The recorded 175 snapshots/4,375 notifications/350 reads and ~14.9 MB JSON are in-process diagnostic observations, not production budgets. Claim improvements only from comparable measurements.

Acceptance still requires zero background transcript payloads/detail subscriptions, one physical watch per shared directory identity and resource release after final unsubscribe. Basic tests cover stalled delivery, admission exhaustion, oversized input, bounded provider decoding and spool quota/disk failure. The full 1/25/100-chat and 1/2/16-detail matrix, five-run cold/warm sampling, 30-minute steady workload and 60-second 10,000-update/s overload qualification are deferred. Their absence is an explicit qualification limit, not a pass.

## Delivery sequence

Each phase is independently reviewable. Replace feature paths directly and remove superseded domain handlers in the same slice. Features not yet replaced keep their current checked paths during development, with one authority/store owner and journal. Do not build a compatibility layer, dispatch through both paths or fall back after a failed WebSocket mutation. Phase completion uses checklists in delivery work rather than separate acceptance tickets or postponed feature-route removal. Dependent work starts once prerequisite deliveries and their applicable evidence are complete.

Verify Effect/T3 port under embedded Electron Node, dev and packaged CJS/restricted PATH on the actual installation; validate real packaged authentication, ACK/cancellation behavior, installed Codex schemas and descendant cleanup. Produce the extraction/dependency/attribution ledger and practical local baseline. No user-store migration, upgrade rehearsal, legacy-writer exclusion experiment or full capacity matrix belongs here.

Depends on this plan’s acceptance. Uses disposable fresh stores. Incompatible upstream/runtime assumptions reopen engineering investigation before production extraction. Completion requires executable evidence for local runtime gates, not just successful typechecking. Dependency installation begins only in the subsequent implementation effort.

Depends on phase 1. Complete client-owned composer persistence and host uncertainty/resource records for newly created state. Test races before/after allocation, failures and restart: no substitute folders/branches, no context rebinding, no resend, no automatic continuation. Retain stable client ownership and host arbitration; exhaustive two-client qualification is deferred. Recovery reconciles actual reservations/journals rather than deleting partial resources. Completion includes applicable local v1/Agents chat and lifecycle scenarios with the installed provider; legacy-import scenarios and broader compatibility qualification are excluded.

Depends on phase 3 buffer/identity integration. Git observation caches remain rebuildable; they are not imported from legacy state. Rebuilding a cache never discards edits/index changes. Retain only necessary observation fallbacks supported by local evidence.
