## Selected architecture

One execution-host authority owns provider processes/credentials, approved contexts, filesystem/Git operations, watchers, durable metadata and reconciliation. Initially compose it inside Electron main. Renderer loss releases connections and views, never host-owned execution. A separately installed service is later work.

Introduce `packages/contracts`, `packages/host`, `packages/client-runtime` and the tracked `packages/effect-codex-app-server` source unit. Keep portable reconciliation in existing pure modules until extraction requires a shared package; do not create a general utility layer. Contracts depend on portable Schema/RPC declarations; host and client-runtime depend on contracts, never each other’s implementation. Neither imports Electron/React. Desktop supplies native/bootstrap/storage adapters and presentation. Existing pure `affected`, `moved`, `reconcileSave`, ordering and reducers stay ordinary TypeScript; React/Monaco own models, undo, focus and accessible presentation.

Effect owns I/O orchestration and scoped resources. Construct host Layers once per host, client supervisors once per desired host, sessions per connection attempt and subscriptions per view. Provider sessions are host-owned. Disconnect/cancellation cannot interrupt admitted provider work. Moving synchronous native work into `Effect.sync` is insufficient: measure host event-loop delay and move blocking execution behind asynchronous adapters while retaining descriptor checks.

Target exact Effect 4.1.0 core/platform-node/node-shared versions and the runtime report’s verified dependency closure. This is conditional on phase 0 runtime checks; no silent downgrade to v3 or mixed package families. The required Redis peer closure is an installation cost, not a running service. Retain Bun/Nx/Monaco and the existing test runner; adapt upstream tests rather than adding a parallel framework. Review unstable RPC/socket/platform APIs and T3’s 4.0.5 patches explicitly.

Adopt the tracked Codex transport as a coherent source unit, retaining generator metadata, schema source and compatibility widenings. Adapt T3 session/driver/supervisor, snapshot/replay/live, coalescer and LiveStreamBudget together. Preserve escode persistence, authorization and command uncertainty rather than importing T3’s application event store or restart continuation. Track upstream pin `305a90dce44b8b7813d951662f13ce8510a3c669`, copied files and local patches in an extraction manifest. Preserve T3 MIT and applicable generated Codex Apache-2.0/NOTICE attribution; produce distribution notices from the actual lockfile/artifacts. Whole-product adoption carries unnecessary provider/native/UI/database closure; isolated throttle copying omits correctness machinery. Both are rejected for this handoff.

## Wire, authority and durable state

Authenticated loopback WebSocket is the domain path. IPC retains narrow, sender/frame-validated local bootstrap and native picker/import/clipboard/Finder capabilities. Bind literal loopback only; use short-lived bootstrap/session tickets, validate packaged Origin/Host and endpoint path, verify persistent host identity and exact initial wire revision before data/commands. Remote routes stay disabled. Capabilities describe support, not authority. Every command revalidates approved root/object identity and resource/session revision at its mutation handoff. A path or native client selection alone grants no remote authority.

Use feature schemas for Chats, Files and Source Control, including typed unavailable/conflict/stale/denied/incompatible/overflow/uncertain results and safe unknown-provider payload presentation. Separate wire revision, storage version, entity revision and provider compatibility. Reject incompatible clients/newer stores without writing. Test minimum Codex 0.163.0 and baseline 0.165.0 against adopted older schema provenance; retain process-group cleanup.

Snapshots capture projection and live tail atomically under a host-start epoch. Applied coverage cursors advance only after complete validated application. Duplicates/overlap are idempotent; gaps, expired replay and epoch changes require bounded resnapshot. Background summaries exclude transcript bodies; only observed details subscribe. Watch/Git events are invalidation hints with explicit rescan, not mutation facts. One Git refresh per checkout plus one dirty bit; retain two-second fallback while visible and reject stale selection results.

Durable command keys bind host, authenticated principal, ID, target and canonical payload digest. Serialize admission against expected state; record admission and dispatch intent before effects. Repeated IDs return status; changed payload/target conflicts. A lost result becomes uncertain and is reconciled through status/history, never automatic resend or a new ID. Restart never dispatches recovered Send/reply/continuation. Receipts cannot make external effects atomic. Replies consume an exact live request once; Stop targets the captured provider/turn or preparation token and remains available without its directory. Stop during preparation cancels that operation, preserving reservations and reporting partial effects.

Adopt the synchronization report’s bounded transient replay and receipt/admission-epoch design. Rotate admission epochs after restart/restore and before pruning permits old submissions to become executable. Never prune nonterminal uncertainty or operation evidence to admit work. Recheck authority on receipt lookup. Revocation invalidates derived sessions and queued admission/control from that device and requests Stop for its originating active work; serialize revocation against dispatch. Completed external effects cannot be undone.

Persist host identity before publishing endpoints. Namespace existing chat/context/provider/recovery identities without regenerating UUIDs, paths, dev/inode identities, reservations or timestamps. Introduce versioned generation manifests, single-writer migration and durable publication of a complete new generation. Quiesce writes, back up originals and reconcile journals before splitting host/client ownership. Refuse mutations on ambiguity; preserve originals on validation failure. Crash at every staged write/selector publication must yield a complete old or new generation. Preserve filesystem identities losslessly.

New stores live separately from legacy files. A new lock cannot stop old binaries that ignore it: require the old app to be stopped before migration, retain untouched legacy backups and document that downgrade launches cannot access the migrated installation. Test concurrent old/new launches against supported packaging/update paths; block rollout if writer exclusion cannot be established. Post-migration rollback must reconcile real effects in the new format; copying an old backup over newer outcomes is forbidden. Backups are not filesystem/provider rollback.

Client-owned composer/recovery records use stable client identity, independent of connection attempts. Host records dirty-state obligations and per-client operation acknowledgements; one client cannot clear another’s protection. Disconnected known-dirty clients block destructive mutations until explicit safe resolution. Unknown unpersisted keystrokes retain the accepted best-effort limitation. Migrate the existing installation’s composer and file recovery to its original desktop client once, without copying it into every future client.

## Bounded bodies and measured capacity

Store transcript text as immutable chunks referenced by message/body revision and byte range. Stream bounded append chunks; page older immutable chunks rather than retransmitting full growing bodies. A host-owned disk spool holds live chunks not yet recoverable from provider history; durable chat/provider identity remains separate. Persist a chunk/index before publishing a recoverable reference. Reconcile orphaned/partial chunks on restart; never attach them to a new host/chat. Client detail cache uses a bounded window and explicit page eviction; summaries contain no bodies. Provider history must be read incrementally or rejected at a bounded decode boundary: truncating after an unbounded JSON allocation does not pass.

Maintain independent limits for decoded frames, in-flight ACK batches, replay, client/host delivery, provider ingress, body cache, socket buffers, subscriptions, watchers, receipt storage and spool disk. Charge encoded bytes before enqueue, including in-flight data until ACK; also measure heap/RSS. Retain control/Stop capacity separately. On spool quota/disk failure, stop accumulating text, mark the affected body partial/unavailable and retain control/status plus provider identity. Stop remains usable; no silent turn cancellation. Continue draining bounded provider frames or fail the provider session explicitly if safe bounded decoding is impossible. Do not claim complete history or bounded memory otherwise. Evict only reconstructible chunks; never uncertainty, drafts or operation facts.

The synchronization report’s numeric values are experiment seeds only. Phase 0 must publish measured values for every limit above, selected from these workloads, with environment, raw samples, variance and exhaustion behavior. Freeze them as versioned acceptance configuration before phase 1 completion; an unresolved numeric gate blocks implementation acceptance rather than becoming a product question.

Run the original baseline diagnostic unchanged, then production Electron workloads at 1/25/100 saved chats and 1/2/16 detail subscriptions, two clients including an ACK-stalled client, approximately 2 MB history and 100,000-character Send, directory bursts and linked-worktree Git invalidations. Use at least five comparable cold/warm runs on the same hardware/build/data. Record request counts, encoded bytes, React Profiler commits, helper/Git invocations, elapsed time, event-loop delay, CPU and post-GC retained heap/RSS. Instrument the original app before replacing it. The recorded 175 snapshots/4,375 notifications/350 reads and ~14.9 MB JSON are in-process diagnostic observations, not production budgets.

Acceptance requires zero background transcript payloads/detail subscriptions, one physical watch per shared directory identity, release to baseline after final unsubscribe, and no growing queue/heap trend over a 30-minute steady workload. Include a 60-second 10,000-update/s overload case: reset/drop the stalled delivery explicitly while healthy delivery reaches terminal state and provider/control survives. Each numeric latency/commit/bytes/activity ceiling must cite the measured original distribution and chosen allowance with rationale; missing production measurements cannot pass. Claim improvements only from paired measured results. Any regression beyond recorded allowance requires investigation or a separately agreed exception, never a fabricated percentage claim.

## Delivery sequence

Each phase is independently reviewable; no automatic fallback from a failed WS mutation to legacy IPC. During transition, unmigrated features retain their checked legacy handlers, with one shared authority/store owner and journal. Route selection is explicit at composition and cannot dispatch an operation twice.

### Phase 0 — compatibility and capacity experiments

Touch root workspace/Nx/TypeScript configuration, desktop bundler/package setup and new contract/transport fixtures. Verify Effect/T3 port under embedded Electron Node, dev and packaged CJS/restricted PATH; validate real packaged authentication, ACK/cancellation behavior, Codex versions, generated schemas and descendant cleanup. Produce the extraction/dependency/attribution ledger and measured capacity table above. Test generation migration, interrupted publication and old-writer exclusion using copies of baseline stores.

Depends on this plan’s acceptance. Uses disposable stores, no user migration. Failure leaves the accepted app unchanged; incompatible upstream/runtime assumptions reopen engineering investigation before production extraction. Completion requires executable evidence for these gates, not just successful typechecking. Dependency installation begins only in the subsequent implementation effort.

### Phase 1 — working local host/client slice

Touch `host/{main,preload,chat-service,chat,tools,project,workspace}.ts`, `src/{chat-state,chat,agents,main}.tsx` (or their existing `.ts` equivalents), new contracts/host/client-runtime/transport units, build exports and desktop fixtures. Keep unchanged Files mutation paths behind the same authority. Migrate existing saved-chat open/history, summary/detail streaming, Send, scoped approval/input, Stop and reconnect/status to authenticated WS; no new chat/resource allocation UI in this phase. Add real Files directory listing AND loaded-directory watch through the same connection/runtime, preserving cached-folder revalidation, degraded watch state and Refresh. This proves non-chat identity, subscription and cleanup before chat architecture is considered established.

Deliver host/provider/client/view lifetime separation and the agreed macOS close/reopen/retained edits/confirmed Quit behavior now. Version and namespace records needed by this slice, including receipts and client recovery obligations; run migration before exposing mutation. Baseline resource preparation remains available to existing chats through host-owned checked adapters, never arbitrary paths.

Completion: packaged UI controls a real installed Codex chat through WS; directory listing/watch works through that socket; disconnect while streaming and after uncertain Send starts no second turn; Stop works with missing directory and during preparation; last-window close/reopen retains text/baselines and live request identity; Quit cancellation/failed Save preserves work, confirmed Quit cleans descendants. Two protocol clients race Send/replies and stale Stop without shipping multi-client UI. Run phase-relevant baseline and security tests. Failed gates block replacing the default path; rollback after mutation must preserve the new store/outcome records.

### Phase 2 — complete chat/context and recovery migration

Move remaining authority from `host/main.ts` and `host/{chat,chat-service,tools,workspace,project}.ts` into host services; migrate `src/{agents,chat,chat-state,worktrees,workspace}` callers. Cover project/No project drafts, revision-checked context edit/first Send, scratch/worktree reservation/preparation, settings, unavailable contexts, closed-project activity and all chat persistence. Carry scoped native project selection through host validation. Remove migrated chat domain IPC routes after parity.

Depends on phase 1. Complete client-owned composer migration and host uncertainty/resource records. Test races before/after allocation, failures and restart: no substitute folders/branches, no context rebinding, no resend, no automatic continuation. Two-client independent text and first-Send/context arbitration must pass. Retain original reservations/journals on rollback; recovery is reconciliation rather than deleting partial resources. Completion includes all v1/Agents chat and lifecycle scenarios and supported provider compatibility.

### Phase 3 — Files authority and preservation

Migrate `host/{project,file-operations,file-operation-state,workspace,native-import}.ts`, `filesystem.c` adapters, `src/{files,main,workspace}` and native bootstrap callers. Contracts cover read/hash/save, create/rename/move/copy/cut/paste/duplicate/Trash/import, recovery acknowledgements and watcher invalidation. Keep platform-local picker/clipboard/Finder references distinct from host authorization. Preserve async bulk copy, 2 MiB editor limit, no-follow descriptor checks, native Trash and accepted external-writer race limits.

Depends on phase 2 identity/storage ownership. Persist per-client dirty/recovery obligations and operation facts before effects and retire protection only after that client’s durable reconciliation. Crash at intent/effect/outcome/ack; race stale saves, external replacement, rename of dirty descendants and disconnected dirty clients. Another client cannot discard their text. Preserve old undo-reset disclosure and new undo behavior. Unsupported Trash never becomes permanent deletion. Completion requires every Files acceptance scenario and mutation/recovery/native-race assertion; no legacy domain path remains for migrated operations. Rollback retains completed facts/staging references and blocks uncertain writes.

### Phase 4 — Source Control and integrated foundation acceptance

Migrate remaining Git/status/diff/worktree queries in `host/project.ts`, `host/main.ts`, `src/main.tsx` and worktree callers. Use the same host/context/session validation and stale-result rejection. Preserve HEAD-versus-editable-working-copy staged comparisons, shared Files/diff models and save-without-stage semantics; introduce no new Git mutation product features. Retain current parser unless an independently tested replacement is needed. Test linked-worktree common metadata, checkout changes during scans, no-Git existing chats and Files restoration.

Depends on phase 3 buffer/identity integration. No separate Git data migration beyond versioned context and cache records; caches remain rebuildable. Rollback drops observation caches, never edits/index changes. Completion requires one in-flight refresh plus dirty-bit convergence, visible two-second fallback, all original acceptance suites and measurements, distribution notices and removed obsolete domain IPC/polling. Retain only measured necessary fallbacks. This completes the local foundation, not remote product delivery.

## Verification and handoff boundaries

Preserve and adapt all named host/UI tests and fake-provider/desktop boot fixtures in the responsibility report. Update imports, exports, workspace membership, Nx build inputs, tsconfig, bundler/native assets and restricted-PATH packaging together. Required commands remain typecheck, lint, test, build, package and smoke; run live Codex checks deliberately in implementation. New protocol tests use deterministic providers/clocks/storage fault injection plus real packaged WS/native integration.

Required cases across phases: snapshot registration/capture/encoding/live-drain races; duplicate/drop/reorder/partial batch and stale epoch; cancellation at every yield; ACK-stalled clients and global admission exhaustion; all command persistence/dispatch crash boundaries; receipt pruning/epoch rotation/backup restore; wrong host/Origin/Host/path, forged roots/native refs, expired tickets, incompatible versions and malformed/oversized frames; revoked device racing admission/reply/Stop; old callbacks and provider wire-ID reuse; disconnected dirty clients and independent acknowledgements; watch/Git failure and stale responses; every lifecycle and multi-client scenario linked above. Reject unsafe action while preserving available work. Run seeded reducer/reference comparisons from the synchronization matrix, retaining upstream budget/coalescer/synchronization tests with adapted semantics.

Manual gates must name build, scenario, operator and result. Recheck keyboard/focus/VoiceOver for close/reopen, reconnect, conflicts, needs-input and Quit; automated accessibility checks do not substitute for VoiceOver. Native Finder/drop/clipboard/Trash scenarios remain honestly recorded as user-owned follow-up where previously excluded; no new manual pass is inferred. Do not reopen those historical exclusions as completed gates or silently waive newly changed native behavior.

Later efforts deliver service installation/autostart, encrypted remote transport/pairing/recovery/revocation UI, LAN/internet exposure, browser/phone interfaces, cross-machine file transfer and multi-host UX. This foundation retains host-bound identities, originating-device attribution, authority interfaces and concurrency tests for them. It exposes none of those remote routes. Collaborative editing, automatic prompt replay, restart continuation and exactly-once external effects are excluded.

No new product vocabulary is needed: use GLOSSARY.md’s agreed host, connection, provider, draft and recovery terms. The consequential decisions are recorded in [host authority and upstream extraction](../adr/0001-effect-host-authority.md) and [versioned recovery and bounded history](../adr/0002-versioned-recovery-and-history.md); the detailed acceptance plan stays here and the decision pointer on the ticket. Before closing the map, re-query children/dependencies and reconcile any newly precise in-scope decision. Runtime experiments are work for the subsequent implementation effort, not a reason to mark this planning map as implemented.
