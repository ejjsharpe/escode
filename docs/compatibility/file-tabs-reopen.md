A successful explicit single or captured bulk close records one action only after the removal snapshot is durably accepted. Failed persistence, failed Save, Cancel and empty closes add nothing. Each action contains exact relative paths, original visual indices, last selected views, view-specific cursor/scroll positions and the closed active identity (or last closed target for an inactive close). It contains no working text, disk baseline, comparison snapshot or model. Reopen restores closed files as kept-open tabs; an unrelated preview is retained.

Concrete history limit: **20 complete close actions per checkout/client session**. Adding the twenty-first evicts the oldest whole action, never part of a batch. A latest bulk action is retained intact regardless of the number of files it closes. This bounds retained actions rather than imposing a new open-file count limit. There is no persistent history, user setting or automatic kept-open-tab eviction.

Cmd+Shift+T consumes the latest action. Missing tabs are inserted at their captured visual indices, clamped to the current order. Existing tabs retain their relative order, selected views, positions and buffers; neither duplicate tabs nor replacement working text are created. The action's selected file regains editor focus, or the exact unavailable editor region receives focus. Newly reopened views use existing current-source restoration; inactive files load lazily when selected. Missing files/checkouts remain exact unavailable targets with the existing Retry controls. Explicit Discard remains final; reopening reads current disk bytes and does not recover discarded text or reverse filesystem effects.

Preview replacement, filesystem operations and project closure do not call explicit close history. Closing/reopening a project can retain its session history in memory, while application/renderer restart starts fresh history and restores ordinary open-file metadata/recovery normally. `src/workspace.ts` exports the session-only `recentlyClosedFiles` map and metadata types for issue 101's known move/Trash reconciliation: update action file paths and active identity for known moves, remove successful Trash references and empty actions. This ticket does not implement that subsequent reconciliation or claim that an older closed reference already follows operations.

The existing Cmd+W capture handler also dispatches Cmd+Shift+T using the same active Files/Source Control, dialog/menu, conflict, input, close and Save guards. It does not broaden Chats/Agents scope or refactor the other shortcuts owned by issue 102. Reopened editors release their temporary read-only state after the transaction.
