# Bounded saved conversation history

Delivery for [Open bounded saved conversation history](https://github.com/ejjsharpe/escode/issues/68), under the [fresh-state amendment](https://github.com/ejjsharpe/escode/issues/61#approved-scope-amendment).

Saved-chat Open and explicit history paging use validated authenticated Effect WebSocket RPC queries. The superseded IPC Open handler is removed; preload routes its existing presentation call directly to the host query, without fallback. Other chat commands and live detail polling remain subsequent replacement work. The host authorizes the saved project, resolves the exact new-format chat association and validates its original checkout/scratch/worktree identity before provider access. Resume must return the same provider ID and cwd. Opening and paging require no Git operation. Missing/replaced contexts retain the association, path and provider identity and reject access without creating a substitute or sending work.

Open requests only the first ascending provider page. First history page and Next history page replace the displayed page, rather than appending an entire conversation. The partial-history status explicitly says other portions are not loaded. Each saved message body and page has a SHA-256 revision over its immutable returned content. Re-reading changed provider content produces another revision; it never changes an already returned value. Provider-owned history is the durable reconstructible source for these read-only pages; this slice introduces no second history store or disk spool. Live append/spool/quota handling belongs to the subsequent streaming slice, and is not claimed here.

Initial bounds are 1 MiB per provider JSON frame, checked in bytes **before concatenation and JSON parsing**, including unknown payloads and unterminated lines; 20 turns per page; 1,000 displayed items and 128 KiB of encoded item content per page. Unknown items render compact JSON within those same bounds. Oversized/malformed pages fail visibly instead of truncating and implying completeness. An oversized or malformed protocol frame fails the provider session and cleans up its process group while preserving saved identity. A single oversized turn can therefore make that portion unavailable; incremental decoding within that turn is not implemented.

Host responses also retain the shared 512 KiB response guard, 1 MiB transport frame limit, sixteen admitted requests per connection, and eight authenticated connections. Client history/open queries share four concurrent query permits and admit at most sixteen pending queries. These are initial bounds, not measured production capacity. The renderer retains one replacement history page per observed chat, releases both page and detail when the final observer leaves, and ignores late results for unobserved chats. Live items and live input requests remain visible alongside an explicitly selected saved page. Navigating back reconstructs the first page from the host; it does not retain hidden pages across projects. Live transcript accumulation remains part of the subsequent streaming work.
