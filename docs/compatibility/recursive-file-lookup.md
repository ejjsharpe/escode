# Recursive checkout file lookup

Implements #110 under specification #93, on the accepted exact-path baseline `5f7e897370b8254616e2196a4fd37a5a48cc7b45`. Scope remains one approved checkout; Agents and recents have separate owners; #113 adds file-change freshness below.

The authenticated `searchFiles` RPC enumerates independently of loaded Files rows. The existing native descriptor launcher enters the validated checkout before executing bundled ripgrep. ripgrep runs without following directory symlinks, with hidden files enabled, no parent/global ignore sources, no configuration arguments and one traversal thread. Checkout-local/nested `.gitignore`, `.ignore`, `.rgignore` and repository `info/exclude` rules apply. Fixed negative globs prune `.git`, `.svn`, `.hg`, `.jj`, `.DS_Store`, `Thumbs.db`, `node_modules`, `bower_components`, and `*.code-search` at every depth. Eligible hidden files and build/dist files remain discoverable independently of Files visibility.

Results are path candidates, not authority to read contents. Activation still calls exact lookup and the shared kept-open editor path, revalidating approval and checkout identity with native no-follow reads, UTF-8/binary checks and the existing 2 MiB limit. A removed/replaced checkout cannot silently retarget a completed scan.

The character scorer, item scoring, query preparation and relevance comparator are extracted from Microsoft VS Code `c254b82c637ec4ee275483e6e4dcb31360a8b7d7`, `src/vs/base/common/fuzzyScorer.ts` and `comparers.ts`. Adaptations remove symbol scoring and unbounded caches, fix platform constants to macOS and use eager standard Intl collation. Every query piece must match; individually quoted pieces require contiguous characters. Matching is case insensitive with case, sequence, boundary, basename/prefix and path relevance. Returned UTF-16 positions drive highlights. No typo correction is added. The shared corpus lives once in `host/lookup.test.ts`, for reuse by later picker work. Research was retrieved from pinned report `ac1258ce68e46e7a2624408388bf37b931cafd73:docs/research/fuzzy-search-vscode-t3.md`; research branches remain unmerged. Microsoft and ripgrep MIT license texts ship in the bundled host notices.

## Resource limits

- Fuzzy query: 256 UTF-16 units; root/path: 4096 units. Existing exact-path input retains its 4096-unit limit. Search request frames are limited to 8 KiB before dispatch, within the existing authenticated socket limits.
- Two concurrent native scans host-wide; excess work fails explicitly with Refresh guidance. Existing connection admission remains 16 requests. Typing waits 120 ms and cancels its previous RPC; socket interruption/disconnection aborts native work. Cancellation leaves the shared chat connection intact.
- Enumeration stops at 20,000 candidate paths, 4 MiB of native stdout, a 16 KiB unfinished path record, or five seconds. Only bounded path metadata is retained; no content index is built. Native stderr retained for failure detection is capped at 2048 characters.
- Scoring charges at most 16 Mi query-by-path cells (the scorer can make both label and path passes), yields every 32 candidates and checks cancellation. A single DP matrix is bounded by the 256-by-4096 input limits. Exhausting the scoring allowance discloses partial coverage.
- At most 100 best results and an estimated 512 KiB serialized result allowance, including positions. Retention is bounded while ranking, rather than collecting all matches. Rendering creates text runs and highlighted positions, not one element for every path character.
- No persistent index or score cache is introduced. Popup-scoped observation is described below; Candidate lists, processes, timers and inherited descriptors end with the request; renderer results end with popup closure. Refresh/reopen enumerates current files and rules.

Capped enumeration/scoring/results, native errors and missing ignore coverage return partial state. Loading and unavailable states are announced; partial searches never claim exhaustive No matches. Traversal order can affect coverage at a cap; refining the query or Refresh does not promise exhaustive coverage beyond these budgets. Ignore-policy freshness qualification is deferred to #114; wider responsiveness qualification belongs to #115.

## Open-popup file-change freshness (#113)

The authenticated `observeFiles(root)` stream is the reusable invalidation seam. It carries only readiness, invalidation or a bounded error, never paths or content authority. The existing Files-tree watch remains unchanged. Native recursive macOS filesystem observation reaches unloaded directories; symlink notifications cannot authorize discovery or activation through links.

Admission is capped at 16 active recursive observations host-wide **before** creating a watcher. Each holds one native recursive subscription, one optional 500 ms timer and its disposer; no per-file/directory index or event-path collection is retained. Events coalesce into at most two invalidations per second per subscription. The wire stream has one sliding pending notification and sticky failure disclosure; ordinary socket request/frame/ack budgets still apply. Native OS event queues are managed by macOS, not an application-sized directory-watch map. No polling scan runs while idle. Each invalidation uses the existing 120 ms debounce, cancels the superseded search, and inherits the two-process/five-second/candidate/scoring/response budgets above. Refresh reinstalls the watcher and rescans after readiness so subscription setup cannot leave a missed-change gap. Errors close the failed native watcher, retain a visible incomplete-coverage warning alongside any search result, and require explicit retry. Query/scope/invalidation generations reject earlier results and activation completions; exact activation still revalidates its captured target through the existing opener and never substitutes a newly ranked row. No working-buffer, journal, approval or chat ownership changes.

## Open-popup ignore-policy freshness (#114)

Built from the #113 integration seam at `63ec6f3a9943d0a13e31bc9956b13fff05d9f85f`. The same authenticated `observeFiles` subscription now covers checkout-local and nested `.gitignore`, `.ignore`, `.rgignore`, plus repository-local `info/exclude` outside linked worktrees. The common Git directory path and device/inode are captured when opening the checkout. Subscription setup and invalidation delivery recheck that identity and reject symlinked or unavailable policy metadata. Discovery also validates repository ownership; a replacement repository is never adopted by an old lookup.

Each subscription keeps the existing recursive checkout watcher and, only when the common Git directory is outside it, one recursive metadata watcher. That watcher filters notifications to `info` and its descendants; it does not observe parent/global ignore sources. Watching the containing metadata directory covers missing, newly created, deleted and atomically replaced `info/exclude`, including replacement of `info` itself. Both watchers share the existing 500 ms coalescer, failure path, 16-subscription admission budget, cancellation and popup/scope/client/Checkout disposers. Maximum retained native watchers are therefore 32 host-wide. Failed setup releases any already-created watcher and admission slot. There is no policy index, polling scan or queued rescan backlog.

Qualification found that ripgrep follows symlinked ignore files even without directory-link traversal. The native lookup launcher now preflights local/nested policy files through no-follow descriptors, requiring readable regular files. It prunes the same fixed default names, skips directory symlinks and bounds coverage at 20,000 directory entries and 128 nested directory levels before running ripgrep. At most 130 traversal descriptors are retained per scan; the existing two-scan admission and five-second subprocess timeout include preflight. The preflight can inspect ignored directories other than fixed prunes, so a large or inaccessible ignored subtree can cause explicit incomplete coverage. It runs in the cancellable subprocess, not the renderer. Git excludes receive equivalent no-follow/type/readability checks in the host. No policy text or new filesystem authority is sent to the client.

Policy coverage errors use the existing partial/unavailable announcement and Refresh/reopen controls; native observation errors use its sticky live-update warning. Query/scope/invalidation generations continue to reject obsolete responses and activation. Files visibility, exact-path opening and separately owned history eligibility are unchanged. A policy scan is a check before ripgrep reads, not an atomic filesystem snapshot: an unrelated writer can change policy after preflight. Notifications are best effort and continuous churn can delay convergence; Refresh/reopen remain recovery. Descriptor-owned policy parsing/enumeration would be required for a transactional snapshot guarantee.
