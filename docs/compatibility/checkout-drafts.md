# Captured checkout drafts

Ticket: [Capture drafts and continue context changes in Agents](https://github.com/ejjsharpe/escode/issues/106), under the [checkout/search specification](https://github.com/ejjsharpe/escode/issues/93).

Checkout-local New chat passes its exact captured checkout through the authenticated draft action. The host validates checkout identity and repository membership before publishing one fresh draft in the existing chat store. Creation does not read a potentially changed/unavailable project default, create a provider, or allocate managed resources. Agents creation continues to use the remembered default. No new chat, composer, buffer or workspace registry is introduced.

The existing context/execution actions preserve chat ID and creation time, client-owned composer text, host serialization and revision checks. Changing a local draft to another checkout or a future worktree continues in Agents while the source editor stays fixed. Future drafts are excluded from checkout Chats until preparation binds the real destination; preparation does not navigate or open editor tabs. First-Send preparation, retained reservations, Stop, failure, uncertain receipts and explicit retry retain their existing authority and recovery paths.

## Saved-project journey regression after the Agents picker

Investigated at integration base `5755abdb0216dd41a4961d19c0c78c9564bce09a` for [the Agents project picker](https://github.com/ejjsharpe/escode/issues/107). The unchanged command `bun run --cwd apps/desktop smoke -- tests/project-drafts.spec.ts --trace retain-on-failure --repeat-each 4` passed twice and failed twice at line 157. A preceding isolated run also exhausted the 45-second test budget; an isolated traced rerun passed.

The ranked hypotheses were delayed creation losing selection, duplicate/hidden composers during tab switching, and an overall host/provider timeout. The failure trace instead localized the race to the owning fixture: immediately after clicking Open project for Beta-linked, it clicked the still-visible Beta Chats/New chat controls before asynchronous project opening completed. The fill resolved Beta's disabled `chats-…Beta-message` textarea containing `Move from local Chats`, then that element detached as the linked checkout opened. Navigation invalidated the old checkout's pending creation selection, as intended; the new workspace had no selected composer. This explains the merger's timeout without implicating the project picker or restart restoration.

The fixture now waits for the exact displayed checkout path after both native project opens, matching the existing navigation journey's completion seam. No production behavior, timeout, first-Send identity, captured-context, retained-text or restart assertion changes. No new suite or private testing API is introduced. Restore remains owned separately by #105.
