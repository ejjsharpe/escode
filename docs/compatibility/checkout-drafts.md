# Captured checkout drafts

Ticket: [Capture drafts and continue context changes in Agents](https://github.com/ejjsharpe/escode/issues/106), under the [checkout/search specification](https://github.com/ejjsharpe/escode/issues/93).

Checkout-local New chat passes its exact captured checkout through the authenticated draft action. The host validates checkout identity and repository membership before publishing one fresh draft in the existing chat store. Creation does not read a potentially changed/unavailable project default, create a provider, or allocate managed resources. Agents creation continues to use the remembered default. No new chat, composer, buffer or workspace registry is introduced.

The existing context/execution actions preserve chat ID and creation time, client-owned composer text, host serialization and revision checks. Changing a local draft to another checkout or a future worktree continues in Agents while the source editor stays fixed. Future drafts are excluded from checkout Chats until preparation binds the real destination; preparation does not navigate or open editor tabs. First-Send preparation, retained reservations, Stop, failure, uncertain receipts and explicit retry retain their existing authority and recovery paths.

## Verification

The existing `tests/project-drafts.spec.ts` journey now checks separate drafts on two fixed tabs, retained text after navigation, explicit existing-checkout handoff and restored Agents selection. The existing `tests/worktree-drafts.spec.ts` journey begins in checkout Chats, checks future-worktree handoff and exclusion from the source Chats view, then reuses its established preparation, restart, preservation and removal assertions. It also explicitly opens the prepared destination to check bound-chat eligibility. The expanded journey has a 120-second budget and allows 15 seconds for preparation to reach live Stop on this machine.

`host/project-drafts.test.ts` adds the distinct captured-checkout publication boundary: a valid linked checkout works even with an unavailable default; wrong-repository, missing and project-less paths publish no draft. Its payload test retains the new optional field through contract decoding. Existing project/worktree/command tests own preparation failure, Stop, uncertainty, retry and serialization checks; no second suite duplicates those journeys.

This is fixture-based local qualification, not live Codex or manual VoiceOver sign-off. Existing best-effort recovery, no replay on reconnect and external filesystem race limits still apply. Lookup, Agents project-picker behavior and file-tab implementation are separate tickets.
