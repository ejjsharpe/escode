# Shared file-tab views — issue 95

Scope: [shared file tabs across editors and comparisons](https://github.com/ejjsharpe/escode/issues/95), under [file tabs](https://github.com/ejjsharpe/escode/issues/92), building on the [ordered-tab foundation](file-tabs-foundation.md). This is not complete parent-spec qualification.

Files activation selects normal editing; Source Control activation selects its staged, unstaged or untracked comparison. Tab activation restores that file's last view, including when the comparison is now equal or unavailable. The labelled **File view** control selects normal editing and applicable comparisons. Changing the Files/Source Control sidebar leaves the editor alone; Chats hides it and returning recreates the same view without changing chat context.

All editable views, including save-conflict Compare, retain the existing checkout-owned model and loaded disk baseline. Comparison originals still come from HEAD (staged), index (unstaged) or empty text (untracked). Save writes only the working file. Compare preserves the existing Compare/Overwrite/Reload/Cancel actions; cancelling Compare returns to normal editing without adopting the external disk baseline. A repeated Save still detects the conflict. Successful Overwrite or Reload retains the selected comparison and renders No changes when resolved.

Client view metadata adds `fileViews` and `editorPositions`, keyed by exact checkout-relative file identity. Positions retain each view's cursor and vertical/horizontal scroll, including the comparison's original side. They contain no file text or comparison snapshots; existing recovery drafts remain authoritative for unsaved text and disk baselines. Host validation rejects malformed paths, view names and positions before replacing stored state. Journal reconciliation moves/removes the added metadata alongside existing file identities. Storage ownership and version rejection remain unchanged. Restoring a conflict view reads the current disk through the host rather than persisting a conflict snapshot.

Equal comparisons display **No changes** while retaining the view. Failed refresh of an existing comparison retains the file/tab/view with an explanation and **Retry comparison**. Available read-only comparisons also offer Retry. The view control retains normal-file selection; any available existing working buffer remains available there. A failed first comparison open preserves the previously displayed file as in the foundation slice. A disappeared change row, Save or refresh does not choose another view or close the tab. Refresh defers comparison loading while a user open is pending, so background observations cannot supersede the newer selection.

## Verification

The existing Electron seam drives real controls and temporary Git repositories. `tests/editable-diff.spec.ts` verifies shared text across staged/unstaged/normal/conflict views, sidebar independence, read-only originals and missing working files, explicit Save, unchanged index/HEAD, and the retained baseline after cancelling Compare. `tests/file-tabs.spec.ts` adds remembered tab views, returning from Chats, disappearing change rows, equal/unavailable/read-only views and Retry, and separate normal/comparison cursor/scroll positions with restored edits after renderer reload. The fixture waits for acknowledged recovery before reloading; this does not claim synchronous per-keystroke recovery.

Red/green evidence: sidebar switching originally removed the comparison; the first Electron assertion failed before implementation. The unavailable journey then failed because read-only comparisons lacked Retry. Returning from Chats failed with an empty editor before editor lifecycle dependencies were corrected. Restoring a save-conflict view with a missing disk file failed before an explanatory Retry state was added. Overwrite failed the view-retention assertion before successful conflict saves kept the comparison. The position journey exposed a fixture recovery timing/key-navigation issue, corrected by using macOS line-end navigation and waiting for persisted recovery. Host malformed-metadata rejection failed before validation; the real move fixture failed before reconciliation carried selected views and positions.

Preview behavior, ordering controls, MRU/bulk close/reopen, complete unavailable-target restoration and the surrounding checkout/search implementation remain owned by later tickets. This slice preserves the existing best-effort recovery and check-before-save guarantees; it does not strengthen cross-process filesystem atomicity. No manual VoiceOver gate applies under the user's 2026-10-31 amendment.
