# Scoped recent files

Implements [Show persistent, scoped recent files](https://github.com/ejjsharpe/escode/issues/112) under the accepted [checkout/search specification](../specifications/checkout-tabs-file-lookup.md), starting at recursive discovery commit `c4b2935ff66ae0304a4cea299c70fc0241cdf3bc`.

Successful normal-file and available working-file comparison opens record only exact checkout root and relative file path in the existing client-owned workspace store. Most recent use moves that exact pair to the front. Failed opens do not add entries. This metadata is independent of file-tab MRU and the session-local Reopen Closed history. No contents, comparison snapshots, approvals or new root membership are stored in history.

Each invocation starts blank and asks the authenticated host to filter history for the current root. Blank input shows recent files in MRU order without recursive enumeration. Typed input filters history separately using the existing pinned scorer, then appends ranked discovery, deduplicating relative paths within that exact checkout. Rows expose Recent files and File results groups, matching highlights, selection and existing keyboard activation. History uses default glob target-basename semantics: `.DS_Store` is excluded even under `node_modules`, while a previously opened `node_modules/known.txt` remains eligible. Local ignore files affect enumeration, independently of history filtering.

History is candidate metadata only. The popup supplies paths only for its current scope root; closed roots remain remembered but are not searched or activated. All history activation still goes through authenticated exact lookup and the shared kept-open opener, retaining directory identity, approval, no-follow, encoding/binary and size validation, current working buffers and stale-response guards. Missing targets retain the current query and editor. The same optional per-root history argument is available to the Agents scope slice when integrated; this slice does not open Agents roots or scratch folders.

## Bounds

- Global client history retains at most 200 exact pairs and 32,768 combined root/path UTF-16 units (at most 64 KiB of UTF-16 string payload). New use retains the newest prefix within both bounds, evicting oldest metadata. Individual roots and paths are at most 4096 units. Host storage validation rejects duplicate, malformed, traversing or oversized entries before replacing acknowledged state. Existing workspace ownership and fresh-format recovery remain unchanged.
- Host history requests accept at most 200 paths and 32,768 path units, validating lengths before constructing a set or scoring. The authenticated search frame cap is 256 KiB before dispatch/schema processing, allowing worst-case JSON escaping of bounded metadata. Other transport budgets remain unchanged.
- History filtering charges at most 16 Mi query-by-path cells and yields while filtering; discovery retains its independent existing 16 Mi-cell budget, two-native-scan admission and enumeration limits. Blank history uses no native scan. Cancellation and checkout identity are checked before returning results.
- Combined output remains at most 100 rows and an estimated 512 KiB including positions. The host caps history before combination and discloses truncated coverage. Discovery retains its bounded ranking and native cleanup. No persistent index, score cache, watcher or second buffer store is added.
