## Behavior

The Files context menu exposes Copy, Cut, Paste and Duplicate. Cmd+C/X/V apply only when the tree itself has focus; Monaco and inline inputs retain text shortcuts. Captured paths come from retained selection, including collapsed descendants, and the host prunes descendants of selected folders. Paste targets the focused folder or file's parent; empty-space menu Paste targets the checkout root. Duplicate and same-folder Copy generate `name copy.ext`, then numbered free siblings.

The system clipboard carries a random token through Electron 45's [asynchronous ClipboardItem API](https://www.electronjs.org/docs/latest/api/clipboard). The host owns the corresponding source paths, checkout identity, inode identities and source types. A forged payload grants no path authority. Paste rejects different checkout identities, replaced sources and changed types. Selection and project/chat navigation cannot change an already captured operation. Successful cuts leave the host reference selection; failed or skipped items remain retryable. Clipboard references are process-local and do not survive app restart; recovery drafts do.

Collisions offer explicit Replace/Keep Both/Skip/Cancel for clean files. Replace explicitly moves the previous clean destination to **macOS Trash before** copying/moving the source; its dialog discloses this and the possible partial outcome. Dirty destination drafts block Replace and offer Open affected files/Keep Both/Cancel. Opening affected files retains them in the ordinary editor/save/discard flow; retry is explicit. Folder/type conflicts offer Keep Both/Skip/Cancel, with no directory merge or tree replacement. Each native item reports its own outcome; completed destination Trash can succeed even if the subsequent transfer fails.

Copy uses the existing descriptor-scoped native helper, launched asynchronously with `spawn`, and never decodes file contents. Recursive preflight rejects symbolic links, hard-linked files, protected `.git` metadata and unsupported object types before staging. The helper copies into an exclusive random sibling, rechecks source/destination-parent and open staging-object identity plus case collisions, then publishes only to a free destination. Failed staging is retained and named in the uncertain intent/report rather than removed through a risky recursive cleanup. Native move also checks occupied case variants. Existing protected app-state checks, sender/checkout approval, exact paths and no-follow flags remain in force.

The shared FileOperations journal and batch-fact overlay coordinate transfers, Trash replacements, moves and persistence. Copies record available source draft text before mutation and reconcile destination drafts over the copied disk baselines; source text and disk remain unchanged. Destination baseline-read failure after native success retains the available source baseline, so ordinary Save still revalidates disk. Native success remains an applied result through later persistence/acknowledgement failure. Copy facts protect against stale navigation snapshots until renderer reconciliation is durably acknowledged. Navigation persistence is allowed during asynchronous copy. Ambiguous publication retains intent, available text and staging facts and blocks subsequent mutations; restart does not infer copy completion from source presence.

Moves use the established buffer/view/path reconciliation, public Monaco destination URI and language, existing save/conflict baselines and restart drafts. Earlier text undo resets with disclosure; subsequent undo works. Transfer progress has a separate accessible indeterminate status while navigation remains available. File editing is temporarily read-only during the originating transfer, including editors opened by navigation; chat Stop stays available. Per-item results use the existing focusable, wrapping status region.

## R2 fixes after fresh independent review

The reviewer reproduced two defects on actual disk/native/Electron paths. Both are fixed at the shared copy handoffs, without adding a mutation service or changing the operation scope.

**Staging replacement.** The native copy command now captures device/inode from its open staging descriptor, holds that descriptor through publication and reopens the original staging pathname with the existing scoped/no-follow flags immediately before rename. A replacement fails identity validation and is neither published nor removed. The existing practical check-to-mutation race remains; this does not claim an atomic cross-process publication transaction.

The copy-staging pathname audit covered creation/open, copying, publication, error classification and restart. Copying uses the held descriptor; the pathname supplies no cleanup authority. Copy staging never sets the save helper's `owned_temp` cleanup variable, and no copy error/recovery path recursively removes it. A flushed native staging marker identifies the opened object to the host. Once staging was opened, or the helper exited by signal, host failure classification keeps the existing uncertain journal even if both the original staging pathname and destination are now absent. Before staging, proven failure can still release the intent for another independent item. Restart never infers a completed copy from a replacement staging object or the presence of the source; incomplete copies remain uncertain with available drafts and the original staging-path fact retained.

Two synchronized tests compile a **separate test-only** helper with `ESCODE_TEST_COPY_STAGE`, pause after copying through the open descriptor, rename the staging object aside, insert a wrong replacement at its original path, and resume. Both folder (2,000 separately checked files) and regular-file (4 MiB) cases reject publication, preserve every original copied byte in the renamed staging object, leave the replacement bytes untouched and create no destination. The shipped helper has no pause protocol. A real-host regression additionally relocates an opened stage before native failure, verifies that absence of both original names does not clear the journal, and checks fresh recovery retains source drafts/uncertainty and blocks new mutations. These are real temporary filesystem operations; the host test compiles its helper separately and observes the ordinary spawn/stdout seam.

**Early-open destination.** Copy delivery now reconciles an already-open clean destination in place, using the public Monaco model edit/undo APIs and the actual copied baseline, with saved/restored view state. It retains the model's destination URI and language. A model already showing the copied text gets its baseline reconciled without a redundant edit. If the destination has acquired different unsaved text, delivery keeps that visible text, writes its corresponding recovery draft over the copied disk baseline and reports the affected destination/source paths for review. Original source models/drafts remain unchanged and are read-only during the originating transfer. Delivery no longer leaves copied text only in an unseen draft that the next edit silently overwrites.

The new real Electron regression performs exactly: dirty `a.ts` plus `b.ts` Copy → pause on the second item's destination collision → Refresh → open the already-copied `target/a.ts` showing its disk baseline → Cancel the second item → observe `SOURCE UNSAVED` in the existing editor and the matching draft. It checks destination Monaco URI/language, a later one-character edit with ordinary undo/redo, disk/draft baseline separation, killed-process restart consistency, and an actual external write followed by an ordinary Save conflict at the destination. Source disk bytes and the cancelled second destination remain unchanged. The first exploratory assertion assumed a multiword typing sequence was one undo group; it was corrected to a single-character edit to test actual subsequent undo behavior.
