# T3 Code lifecycle: evidence for the live policy discussion

Research for [What should closing a client, quitting the desktop app and shutting down an execution host mean?](https://github.com/ejjsharpe/escode/issues/53), under [Establish escode’s Effect host and client foundation](https://github.com/ejjsharpe/escode/issues/49). **Evidence only; no escode policy is ratified and the HITL ticket remains open.** No product terminology changes are proposed.

Inspected 2026-10-30: map pin **305a90dce44b8b7813d951662f13ce8510a3c669**; live upstream main **32ecd71726fee16f335484c1f95cbce126d461f6** (GitHub API committer date 2026-10-30 09:17:08 UTC). All source links below use the map pin unless marked drift. Read source and tests in an existing detached clone; fetched upstream main. No installation, application edits, provider calls, runtime tests or destructive experiments. **Direct** means implemented code/test assertions; **Inference** means a consequence of those paths; **Unknown** means this investigation establishes no guarantee.

## Four different lifetimes

**Direct:** server startup owns the orchestration effect worker and recovery; client RPC owns a socket; the connection supervisor replaces lost sessions. Provider thread resume is a separate adapter call using provider identity. **Inference:** view subscriptions and client connectivity are not ownership of the agent execution. Closing a read surface should not be described as provider Stop. [Server ownership][host], [worker][worker], [socket][socket], [client reconnect][reconnect], [provider resume][provider-resume].

## Cases

1. **Leave a chat view or close a file/preview surface.** **Inference:** losing the view/subscription alone does not cancel host-owned agent work; the host effect worker is independent of the view. This is an ownership conclusion, not a tested guarantee for every tab type. A T3 preview browser tab, terminal tab, editor surface and conversation are different resources; do not call every close action “close chat.” **Direct:** file save sessions flush when their final surface releases and retain unsaved text in mounted client atoms across preview closure; an inspected test covers reopen after unavailable write access. [Ownership][worker], [file surface release][save-default], [retained buffer][draft-memory], [test][draft-test].

2. **Close/collapse a project versus Remove project versus archive.** **Unknown:** no escode-style “close project editor but keep a saved project in Agents” operation was established in the inspected T3 project command interface. Do not equate navigation/collapse with removal. **Direct:** Settings Remove project confirms and submits deletion with `force: true`; server deletion includes normal and archived child threads, rejects nonempty projects without force, durably deletes children before the project, and can be retried after partial failure. Child deletion cancels active/queued/waiting run records and schedules provider detach. This is deletion of T3 records, not proof of repository-folder deletion. [UI][project-ui], [cascade][project-delete], [run cancellation][delete], [detach][delete-detach], [concurrent-delete test][project-test].

   **Direct:** archive is a **thread** operation here, reversible through unarchive; it is not a demonstrated project archive feature. UI eligibility rejects preparing/starting/running states and some queued states; it is not a universal “all pending input blocks archive” rule. Archive detaches live sessions, revokes their MCP credentials and schedules terminal cleanup, as well as clearing watch/share state. [UI][archive-ui], [exact eligibility][archive-eligible], [archive/unarchive state][archive-state], [effects][archive].

3. **Browser tab closes, socket disconnects, network loss, client crashes.** **Direct:** socket disconnect fails that transport session; the supervisor treats transient loss as reconnectable, with retry/backoff. An inspected test asserts reconnection after involuntary close. The transport disables in-place transient retries. **Inference:** an admitted agent turn can continue while the client is absent because its worker belongs to the server; a lost client does not by itself invoke host shutdown or provider Stop. Reconnecting reads event history/snapshots; replay of history is not replay of a prompt. **Unknown:** uninterrupted execution under provider timeouts, host sleep/resource exhaustion or arbitrary driver behavior. [Socket][socket], [reconnect][reconnect], [backoff][retry], [test][reconnect-test], [bounded history replay][stream], [host ownership][host].

   **Direct:** Electron renderer crash/oom/killed/abnormal-exit has a bounded reload recovery path. **Inference:** renderer loss can leave the desktop main process/backend alive; this differs from main-process death. Client-memory-only state may be lost. [Renderer recovery][renderer], [buffer storage][draft-memory].

4. **Desktop window close versus Quit, including macOS.** **Direct:** closing all windows invokes Quit on non-macOS; on macOS it does not, and app activation reopens/focuses the window. Quit prevents the first quit event, destroys windows, requests desktop shutdown, waits for completion, then quits. No active-turn Stop-and-Close confirmation appears in that handler. A repeated quit after a 10-second stall can force exit. Tests inspect window destruction before backend shutdown. **Inference:** macOS last-window close can leave owned backend work alive; Quit stops owned bundled backends. Neither is a universal “desktop close detaches” rule. [Platform handling][mac], [quit][quit], [stall escape][quit-stall], [test][quit-test], [backend scope ownership][pool], [stop finalizer][backend-finalizer].

5. **Bundled local backend versus separate/remote server.** **Direct:** desktop-owned backend processes have scoped stop finalizers and SIGTERM with force-kill fallback. Desktop-mode authenticated bootstrap also watches launcher loss on POSIX every two seconds; Windows and init-parent cases skip that polling. Thus even abrupt desktop main-process loss is not intended as durable background execution for a bundled backend. **Inference:** quitting a client does not terminate a separately owned remote/headless/service server through these local-child finalizers. Server lifetime then depends on its own launcher/service, not the browser. **Unknown:** Windows orphan cleanup and all external provider descendants after forced death; no cross-platform survival/termination guarantee. [Spawn][backend], [finalizer][backend-finalizer], [watch][launcher], [desktop-only gate][launcher-gate], [watch test][launcher-test].

6. **Unattended active turns and pending approvals/input while only the client is absent.** **Inference:** admitted work can run; requests can remain pending for a returning authorized client while host/provider callbacks remain live. Client reconnect is not automatic approval, a synthesized answer or a provider restart. **Unknown:** indefinite request retention, timeout-free waiting or every provider’s behavior; these were not demonstrated. When the **host** stops, handling changes: **Direct:** recoverable live user-input questions become message-answerable; other live requests become cancelled on shutdown or expired at startup, with `not_resumable` capability. Existing message-capable requests are treated separately. [Host execution][host], [question selection][recovery], [request transitions][requests].

7. **Explicit server stop.** **Direct:** normal server finalization closes command readiness, interrupts the effect worker, prepares restart continuation, shuts down provider sessions, and reconciles shutdown state. This is not a “wait for all turns to finish” path. Installed service plans stop through `systemctl --user stop` or `launchctl bootout --wait`; stopping one child PID is a different action from stopping its supervisor. **Crucial:** graceful stop can persist continuation intent when enabled; stopping the host is not necessarily permanently abandoning the interrupted task if the same state is later reopened. [Shutdown sequence][shutdown], [continuation preparation][prepare], [systemd stop][service-stop], [launchd stop][launchd-stop].

8. **Host crash/restart or machine restart.** **Direct:** startup reconciles saved runtime state and starts the worker; stale runtime callbacks are not resurrected. T3's `continueThreadsAfterServerUpdate` defaults **true** and gates restart recovery/preparation. Eligible unfinished root work needs matching provider/session/native-thread identity; archive/delete/settlement/snooze, unresolved non-message requests and secrets can block continuation. User Stop and maintenance-command exclusions have tests. The continuation sends a **new system-generated message** `Continue where you left off.` (sometimes with a background-work note), not a literal replay of the original prompt. It records deterministic command identity and links the source run. [Default][default], [recovery setting][recovery-start], [startup][host], [eligibility][eligibility], [identity][identity], [new message][continue], [identity tests][continuation-test], [Stop tests][stop-test], [snooze/secret tests][continuation-guard-test].

   **Inference:** machine reboot cannot preserve a running local process; once the host is actually relaunched with its surviving state, the same reconciliation/conditional continuation can apply. **Direct:** installed systemd units request `Restart=always`; launchd jobs use `RunAtLoad`/`KeepAlive`. **Unknown:** automatic host availability after every reboot: installation, login/session activation, supervisor configuration, credentials, disks and provider support still matter. Neither process resume nor exactly-once filesystem effects are established. [Systemd][service], [launchd][launchd].

9. **Provider session reconnect versus client reconnect.** **Direct:** provider-session management checks whether the provider thread is loaded and calls the adapter's `resumeThread` when needed. The client supervisor only replaces a transport session. Host restart continuation is a third operation, issuing a new message. **Inference:** restoring a client socket does not imply resuming an interrupted provider turn, and loading saved provider history does not prove the old live approval callback still exists. [Provider][provider-resume], [client][reconnect], [lost callbacks][recovery], [continuation][continue].

10. **Uncertain Send, lost acknowledgement and prompt replay.** **Direct:** unary RPC invokes the current session once; socket protocol transient retries are disabled. Commands can supply an ID; otherwise an ID is allocated. Orchestrator receipts replay an already-handled result for the same ID/thread and reject a cross-thread ID conflict. **Inference:** a disconnect after commit but before acknowledgement is still uncertain to the client; reconnect alone is not evidence that Send failed and is not a reason to submit a fresh command. A new command ID bypasses same-ID deduplication. These receipts do not prove exactly-once provider execution or external effects across process loss. **Unknown:** a complete durable client outbox/reconciliation guarantee for every composer failure path; this report does not certify one. Keep this separate from the explicit restart-continuation message above. [One-shot RPC][rpc], [socket retry settings][socket], [ID allocation][command-id], [receipt behavior][receipt].

11. **Dirty editor buffers and interrupted filesystem operations.** **Direct:** T3's inspected file editor autosaves with a 500ms debounce; final surface release flushes, and unavailable/failed writes can retain unsaved client-memory drafts for reopening. This differs from escode's explicit save/recovery-draft policy. **Inference:** browser/renderer/process death can lose text not yet durably written; final unmount flush is not an awaited application-exit barrier. **Unknown:** no crash-durable file-buffer recovery was established. [Save sessions][save], [debounce/flush][save-default], [in-memory retention][draft-memory], [reopen test][draft-test].

   **Direct:** the inspected workspace writer validates its target then calls `writeFile` with `O_TRUNC` (and `O_NOFOLLOW` where available), followed by an entries refresh. **Inference:** host death during this path can leave a truncated/partial file; the shown path has no staged atomic replacement or durable operation-intent reconciliation. **Unknown:** no escode-equivalent rename/move/copy/Trash journal was established by this bounded read; provider tools and other Git/filesystem paths require separate analysis. Do not generalize chat/event persistence into a filesystem-transaction guarantee. [Writer][fs-write].

## Current-main drift and limits

GitHub API plus a local `git diff 305a90dc..32ecd717` showed 14 changed files. None of the cited lifecycle/recovery/transport/file-save paths changed. Relevant operational drift: `serviceProtection.ts` now sets `detached: false` for sudo so protection setup can prompt for a password; associated CLI wording and tests changed. This improves installing service memory/OOM protection, not a survival guarantee. Other changes concern timeline rendering and thread-detail state. [Current-main fix][drift].

The tests cited are **inspected evidence, not tests run in this session**. No OS close/quit/crash, power-loss, remote-provider or real approval experiments were performed. Conclusions apply to the pinned source and the narrowly checked main delta, not every released/installed T3 build. Existing escode Stop-and-Close/restart semantics remain the constraint until the user explicitly accepts an amendment on the live HITL ticket.
