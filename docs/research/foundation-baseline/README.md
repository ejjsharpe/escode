## Responsibility and dependency edges

- `host/main.ts` is the composition root and **authority boundary**, not just an IPC router. It creates `Chats`, `ChatService`, `Workspace`, `FileOperations`, `Project` caches and project-session identities, and owns native-import handles, clipboard/drag captures, mutation exclusion, protected app-state paths, dialogs and shutdown. These dependencies are closure-local. Extracting only a chat service does not extract authorization or safe resource preparation.
- `host/preload.ts` exposes the frozen `window.escode` surface using `contextBridge` and `ipcRenderer`. `nativeFiles` resolves genuine browser `File` objects through Electron `webUtils`; watch callbacks correlate root and subscription UUID and remove listeners on disposal. It does not enforce main-process authority. `src/main.tsx` declares the renderer surface using bridge types; there is no independent shared schema package or versioned transport contract.
- `src/chat-state.ts` owns a renderer-lifetime `Map<project|null, ProjectChats>`. `useSyncExternalStore` subscribes presentation; stores retain lists, unsent draft text, snapshots, pending/responding locks and errors. ChatView, project activity indicators and each Agents ChatRow call this hook. There is one 300 ms timer **per subscribed store**, not one per row. Every successful per-chat snapshot allocates new dictionaries and notifies **every** store listener, even if unchanged. The polling guard prevents overlapping refresh batches. Last unsubscribe stops its timer; the global map retains the store and its snapshot data. That retention is code ownership, not proof of a leak.
- The chat path is UI → `ProjectChats` → preload `chat` invoke → `main.ts` sender/operation/project checks → `Chats`/checkout authorization → `ChatService` → `tools.connectCodex` → one stdio app-server process per connected chat. Provider notifications update host session state, not renderer state directly. Renderer refresh obtains whole snapshots. `ChatService.snapshot` structured-clones all items, settings and requests; the IPC handler uses `inspect`, which additionally loads saved metadata and validates its directory. Handler membership checking performs another list read first.
- `host/chat.ts` owns `chats.json`, serialized read/modify/write operations, stable chat/project/checkout/thread identity, legacy ordering, draft/bound state, first-send outcome, directory identities and scratch/worktree reservations. Reads reread the JSON file; writes replace a temporary file by rename. Unlike `Workspace`, this writer does not explicitly fsync file and parent. Provider history is owned by Codex; escode saves associations and drafts. Do not replace uncertain creation with a new provider thread.
- `host/chat-service.ts` owns live sessions, opening/sending/context transitions, request token→wire-ID routing and epoch guards. `send` durably retains text, authorizes, prepares scratch/worktree resources, connects/binds if needed and records uncertain intent before `turn/start`; accepted text is cleared only after success. `open` resumes a known identity, paginates full history and never sends a turn. Stop clears request tokens and interrupts the original turn without validating filesystem availability; answers validate request ownership and execution directory before responding. Context changes and setup exclude one another. Snapshots expose `any` settings/request params: static TypeScript shapes are not wire validation.
- `host/tools.ts` owns executable discovery/version checks, protocol initialization, newline JSON RPC, request timeouts, pending replies and process groups. It uses Node child processes/readline/fs/path/os, not Electron. Each connection spawns detached in the checkout; close fails pending work, SIGTERMs the group and escalates after 300 ms; `finished` represents cleanup completion. RPC timeout is 30 s. Event callbacks, wire IDs and session epochs must remain connection-scoped. No transport backpressure/bounded history queue is established by this code.
- `host/project.ts` owns checkout descriptors/dev+inode identity, Git/common-repository identity, lexical and physical path validation, text decode/size/hash checks, file watching, helper invocation, Git commands, worktree creation/ownership/removal. It imports `findExecutable` from tools. Most native/Git calls use synchronous `execFileSync` through `io`, handing the helper directory fd 3. Recursive copy/import preflight and copy spawn asynchronously. Thus an `async` public method is not evidence of nonblocking work.
- `host/filesystem.c` is a **macOS capability boundary**: descriptor-relative operations with `O_NOFOLLOW_ANY`/`O_RESOLVE_BENEATH`, explicit metadata/type checks, exclusive staging/publication, native copy and CoreServices Trash, and Git launched from the validated directory. Node lexical validation alone is not equivalent. `host/native-import.ts` retains validated external descriptors/ancestry and invokes helper checks; original sources remain intact. Native imports cannot be represented by an arbitrary client-supplied path with equivalent authority.
- `host/workspace.ts` owns validated `workspace.json` and separate host approval records (`approved-projects.json`). Serialized replacements write a temporary file, sync it, rename, then sync the parent directory. Renderer memory cannot grant approvals. `src/workspace.ts` is shared renderer state, `useMemory`, close registrations and `persist`/`flush`; each persist structured-clones the **whole** workspace before IPC. Recovery buffers carry both available text and disk baseline. The host write queue orders persistence; renderer `flush` tracks the latest persistence promise and its failure.
- `host/file-operations.ts` coordinates durable intent before native mutation, actual outcomes, workspace reconciliation, completed/uncertain states, batch facts and renderer acknowledgement. It depends on Project + Workspace + shared pure reconciliation. An applied mutation can return `persistencePending`; failure to persist must not be reported as failure to mutate. Stale renderer snapshots are reconciled with batch facts inside the storage queue until acknowledgement. Uncertain outcomes retain intent and block later mutations. Recovery compares object identities, not absence alone.
- `host/file-operation-state.ts` exports pure `affected`, `moved`, `reconcileSave`, `reconcile`. It imports only types, and is **runtime-imported by the renderer**. It maps draft paths, saved baselines and view/tree memory. Its host directory location does not make it host-only. Keep one implementation across the disk/workspace/model handoff.
- `src/main.tsx` composes projects/Agents, checkout selection, file/diff views and chat indicators. It owns Monaco models, unsaved buffers, view state, recovery persistence, conflict UI, mutation reconciliation/ACK and close locks. Old diff side stays read-only; editable new side shares the file buffer. Staged baseline is HEAD with working copy edits visible. Editor disposal is distinct from model/buffer retention. `src/files.tsx` owns lazy tree cache/epochs, selection/focus, inline actions and clipboard/drag/import UI; host validation remains authoritative. Watch changes rescan loaded paths; focus, activation and Refresh recover missed events.
- `src/agents.tsx` catalogues saved project and No project chats, including closed editors; it reuses ChatView and project stores. Catalogue **and targets** load immediately and every 1 s. `src/chat.tsx` owns conversation presentation, effective settings, request controls, explicit Retry/Send/Stop and draft context choices. It renders the full `snapshot.items` collection; no history virtualization is present. `src/worktrees.tsx` owns explicit existing/new-worktree choices and branch display. CheckoutBranch loads status immediately and every 2 s. CheckoutView also refreshes status every 2 s, with selected diff refresh in Source Control. Hidden mounted checkouts/project stores can continue polling; visibility alone does not release them.

### Every main-process IPC handler

All six handlers validate sender webContents, main frame and exact loaded document URL. The BrowserWindow uses context isolation, sandboxing, no Node integration, denied permissions/new windows/navigation and CSP. These local Electron checks need an equivalent authenticated transport boundary later; they are not portable authorization by themselves.

- `tools:status`: no arguments; executable/version/protocol readiness through tools.
- `native-import-capture`: isolated preload native-file resolution → validated NativeImport handles → UUID capture, expiry 60 s. Main sweeps every 10 s and clears handles on navigation, renderer loss or window close.
- `lifecycle`: `load` restores workspace, host-approved projects and saved chat associations, then reconciles intent; `persist` passes through FileOperations; `dirty` opens Save/Discard/Cancel; `prepare` prompts active-work quit; `finish` closes editor membership or shuts down the app. Unknown operations/argument shapes reject.
- `files-watch`: validates root/id/path list and project-session ownership, replaces/disposes the matching subscription, forwards `files-changed` only while its captured project/session remains current. Navigation, renderer loss and close release subscriptions.
- `project`: native chooser `open`; file-operation ACK; drag/clipboard capture and `transfer`; create entry, batch Trash, save, move/Trash; managed worktree inventory/remove/options/create; status; entry actions (path copy/Finder reveal); files/filter/read/diff. Main owns dialogs, clipboard, captured source/destination identities, app-state protection, origin revalidation around awaits, dirty-destination and active/recovery-work guards, and per-item results. These are substantial service responsibilities currently coupled to Electron. Reads are also validated; renderer view roots do not create capability.
- `chat`: catalogue/targets and saved-list access; draft creation/context/execution choices; legacy create; open/snapshot/stop/disconnect/draft/send/answer. Root may be project identity or null. Closed editor projects retain session authority. Snapshot/draft access can preserve unavailable records; executable actions require authority. `checkout()` derives secondary-checkout access from saved associations and checks original identity; `send` additionally validates project/repository and prepared worktree identity. Stop intentionally bypasses path lookup. Prompt and answer limits are checked before dispatch; unknown operation/arity rejects.

### Config, exports, fixtures and build reach

There are no barrel exports/shared contract package. Host bridge interfaces are declared in `host/project.ts`, `host/workspace.ts` and renderer `chat.tsx`; renderer imports SavedChat, ChatSnapshot/LiveRequest, Project/Document/Change, FilesMemory/ViewMemory/WorkspaceState plus runtime reconciliation from host paths (see imports.json). An extraction must reach those consumers and preload/global declarations together.

Root package/Nx tasks delegate to desktop; `bun.lock`, both package manifests and `tsconfig.json` govern runtime/type closure. `vite.config.ts` builds React/StyleX and Monaco workers; host tests run in Vite Plus with plugins disabled. `scripts/host.mjs` bundles main and preload to CJS with Electron external; `scripts/filesystem.mjs` compiles the macOS helper with CoreServices. Packaging includes the helper as a resource, and main selects resource versus dev path. Playwright is single-worker with a 45 s default test timeout. `tests/desktop.ts` selects packaged/unpackaged app and isolated user data/PATH. Protocol fixtures are inline generated executables in tests; real-provider tests are opt-in. Include those fixtures, restricted-PATH launches and main-process evaluation seams when moving composition or IPC. Adding Effect alone does not validate packaged resolution or service lifetime.

### Lifecycle policy, including races

Closing a project editor saves/discards/cancels available dirty buffers and removes editor membership; it retains approval, chats, live requests and worktrees in Agents. Whole-app quit with active work requires **Stop and Close**, defaults to Cancel, flushes recovery, interrupts active turns (at most 500 ms wait per interrupt), invalidates opening epochs, closes connections and awaits process-group cleanup. Restart restores metadata/drafts/history on explicit connection, never an active turn. Daemonized descendants outside the owned group and power-loss durability are outside the guarantee.

Read `host/shutdown.test.ts`: four tests cover interrupt plus resistant descendants while another project runs, shutdown during open, failed initialization cleanup, and shutdown before delayed saved-metadata read can spawn. Read `tests/lifecycle-races.spec.ts`: file editing and duplicate closes lock while persistence is delayed; delayed IPC chat open survives **editor** closure without reopening its tab. `host/project-drafts.test.ts` and `scratch.test.ts` add preparation/startup races. `tests/lifecycle.spec.ts` covers cancel/failing save, durable discard, acknowledged-draft SIGKILL recovery and app quit versus editor close. These distinguish client detachment from execution-host termination; changing lifetime needs the existing lifecycle decision ticket, not an inferred migration change.

## Measurement method, limits and rerun gates

Run `bun docs/research/foundation-baseline/measure.ts > /tmp/foundation-results.json` from repository root on macOS with installed Git, clang/CoreServices and Bun. It installs nothing, compiles the existing C helper into a temporary directory, uses only isolated generated files, then cleans up. Assertions verify request/list membership, notification accounting, no polling after final unsubscribe and native watcher sharing/release. Do not run against user data. The diagnostic inspects TS-private fields intentionally; this is an unmerged evidence asset, not production API.

The chat diagnostic transpiles **actual** chat-state source, replacing only the React hook adapter. Its in-process bridge calls real ChatService.inspect/Chats, with the handler's membership list check, but excludes Electron sender checks, approval/checkout composition, Electron serialization and process transport. Sessions/history are seeded fixtures; stream deltas go through the actual service event handler every 20 ms. One store has 25 listeners in the background case, approximating 25 same-project Agents rows. Every sample is warmed with load/refresh, then sampled for 2.1 s; the timer is frozen and any batch drained before listeners detach. Three repeats per workload; JSON sizing and GC add diagnostic overhead. This is a host/store baseline, not measured UI performance.

`calls` counts shim bridge invocations, **not actual IPC**. `payload` is the sum of `Buffer.byteLength(JSON.stringify(result), 'utf8')` for successful returned values; arguments, framing, Electron structured-clone overhead and network encoding are excluded. `reads` counts actual Chats.list calls (each reads/parses chats.json), **not filesystem syscalls**. Latency starts inside shim dispatch and stops before JSON byte counting. Notification totals count listener invocations, **not React commits**; React batching can change commit counts. Heap delta is Bun heapUsed after forced GC minus after warmup GC; it is an endpoint sample with live stores retained, not a leak test, total RSS, Chromium or production Node memory.

Native samples use a real empty Git repository containing 100 untracked text files. Count instrumented Project.io helper invocations and the subset with `git` operation; initial Project.open/discovery and fixture generation are excluded. Three files/status operations and three bursts of 20 writes are sampled. Watch latency is first callback after writes begin with 10 ms observation granularity; watcher counts inspect the actual host map. No kernel syscall trace was taken.

### Observed diagnostic results

Final run: macOS 26.3.1 (25D2128), Apple M1 Pro arm64, 16 GiB RAM, Bun 1.4.4, Git 2.50.1 (Apple Git-155). System Node is v26.13.0; raw `process.version` reports Bun's Node-compatibility value v26.3.0, not an Electron or system Node execution. Three samples per case; all diagnostic assertions passed. A preliminary harness assertion exposed an in-flight unsubscribe counting error; the final harness drains the sample and excludes subscribe's asynchronous warmup load. Preliminary output was discarded, not treated as a product failure.

- Empty subscribed store: zero sampled bridge calls/bytes/notifications. Its timer still ticks but has no chats to fetch. This excludes Agents catalogue/targets polling.
- One idle chat: 7 snapshots, 1,778 JSON result bytes, 7 listener calls and 14 Chats.list reads per approximately 2,101 ms sample. Median shim request latency across repeats was 1.552–2.132 ms; maximum observed 4.592 ms.
- 25 idle chats, 25 same-project subscribers: 175 snapshots, 45,430 result bytes, 4,375 listener calls and 350 list reads per approximately 2,101 ms sample. Per-sample median request latency ranged 3.754–5.010 ms, maximum observed 7.648 ms. This confirms shared polling but listener fan-out on each result; it does not measure 4,375 React commits.
- Long streamed history: 7 snapshots, 14,899,957–14,900,257 result bytes, 7 listener calls and 14 list reads per approximately 2,101 ms sample. Per-sample median request latency ranged 2.719–5.033 ms, maximum observed 6.125 ms. Full-history amplification exists even when each delta is small; no production throughput limit is inferred.
- A 100-entry directory listing: exactly 1 helper, 0 Git commands, 3,591 JSON bytes; operation duration min/median/max 3.563/4.362/4.884 ms. Status on the same unborn branch: 2 helpers, both Git commands, 3,914 bytes; 37.708/39.091/40.151 ms. These counts exclude main's checkout/association authorization and other timers.
- Three native watch bursts: one coalesced callback each, first callback min/median/max 109.355/154.174/156.145 ms. Two root subscribers shared one native watcher; removing one retained it and removing both left zero. No syscall count or visible renderer-rescan timing was measured.
- Forced-GC heap endpoint deltas are in raw results: empty +654 to +12,539 bytes, one idle +18,403 to +24,337, background −1,192 to +22,302, long stream −2,170,090 to +78,491. Negative/noisy samples demonstrate why these short Bun runs cannot establish retained-memory growth or savings. Production retention remains an explicit gap.

### Unmeasured quantities and concrete follow-up protocol

No dependencies are installed in this worktree; Electron/React/Monaco/Playwright and project test runners were therefore not launched. No full application check, live Codex turn or install was attempted. A successful Bun diagnostic does not certify Electron Node compatibility or the application suite.

Before treating a future implementation as a performance improvement, run the following against **both** this pinned application source and the candidate, same lock/runtime/machine and isolated user-data fixtures. Record 3 warmup runs and at least 5 measured 60 s samples per workload (median, p95 and min/max, including errors), plus a 10 min soak with before/after GC where supported. Numbers are required evidence then, not invented now.

- Instrument preload invokes and main handler completions with correlated IDs, operation/root/chat, request/result JSON byte estimates and monotonic timestamps. Count calls and bytes per second separately for chat, catalogue/targets, status/diff, persist and watches. Electron wire byte size remains unknown unless a supported serializer measurement is added; do not equate JSON estimates with wire size.
- Instrument renderer store update/listener counts and React Profiler commit count/duration, and observe input-to-painted-update and visible Stop completion in the actual window. Use an enabled profiling build consistently. Cover zero-chat idle, 1 and 25 connected background chats across 1 and 5 projects, one visible 2,000-item/roughly 2 MB history streaming 50×100-character deltas/s, and at least 100 rapid project/chat/checkout switches. Distinguish idle connected provider processes from the seeded in-process fixtures here.
- Repeat the generated tree and long-copy journeys, and 20-file watch bursts; count loaded subscriptions/native watchers, time first visible rescan, then switch/close to assert zero released resources. Instrument helper spawn/exec and Git argv category; obtain filesystem syscall traces only with available tracing permissions. API calls/helper counts cannot stand in for syscall counts.
- Disconnect/reconnect 10 times with saved long history, both while idle and with a pending request; count history pages/bytes, reconnection latency, old-callback rejection and **zero automatic turn/start**. Inject slow responses, duplicate/stale events, lost terminal result, unavailable directory and renderer loss. Existing tests cover many safety outcomes; sustained slow-consumer flow control, bounded streaming buffers, multi-client and cross-machine routing have no current baseline or transport implementation.
- Sample main/renderer/provider RSS and heap separately after warmup and after soak; report retained history/store/model/subscription/session counts after navigation/closure and after GC. Current global stores/live sessions intentionally retain data, so compare equivalent ownership states. Track workspace size and persist frequency under many dirty buffers; this diagnostic does not benchmark whole-workspace clone/disk sync cost.

## What this clears, and what stays open

The inventory identifies the concrete host/client seams, preservation checks and measurement definitions needed to discuss architecture without assuming that chats are the whole host. It establishes small reproducible host/store/native samples and labels the missing production baselines. It does **not** choose Effect layers, a synchronization protocol, a lifecycle amendment, new product terms or a numeric performance budget. Therefore no glossary/ADR change is warranted here.

The already-open responsibility, synchronization, authority, lifecycle, multi-client and phased-plan tickets own the decisions exposed by this evidence. The phased plan must carry the missing actual IPC/React/retained-memory/reconnect measurements as explicit acceptance work before performance claims; that is a known measurement gap, not unspecified architecture fog. No additional decision ticket is needed merely to duplicate these existing questions.
